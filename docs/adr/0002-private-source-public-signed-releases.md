# Private source, public signed releases

Keep the SwimTunes source repository private, but publish signed Windows binaries and update metadata through a separate public release repository. A portable app cannot anonymously fetch releases from a private source repository without embedding credentials; this split preserves app source privacy while allowing unattended startup updates. Public releases must also include any third-party materials their licenses require, including matching FFmpeg notices, build details, and corresponding source when required by the chosen build. Select and check the FFmpeg build against the [FFmpeg distribution guidance](https://www.ffmpeg.org/legal.html) before the first signed release. The updater accepts only a newer build with a verified trusted signature and designated publisher, and retains the current signed build with a warning when download or verification fails. Signing is required before friend-facing distribution; without access to the actual Windows headphones, the first release must be labeled beta and cannot claim verified playback.
